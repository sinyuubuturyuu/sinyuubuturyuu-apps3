開発環境移行ガイド

最新のコードを基点に、Firebase接続先・キャッシュ・実行時の接続先まで確認して安全に切り替えます。

重要事項

  • 本番 Firebase sinyuubuturyuu-86aeb へ書き込まない。
  • クラウド開発環境 sinyuubuturyuu-dev とローカル Emulator を区別する。
  • main を直接変更せず、当日作成した作業ブランチだけを使う。
  • この案内の更新だけでは、現在開いているアプリの接続先は変わらない。

1. 依頼文をコピー

日付は作業当日の値へ置き換え、最新mainから新しいブランチを作ります。

次の2つのdocsをすべて確認し、最新の upstream/main を基点に、開発環境への切替を行ってください。

参照するdocs:
- docs/firebase-auth-email-password-spec.md
- docs/firebase-auth-pc-spec.md

ブランチ:
- 作業当日の日付で feature/dev-env-YYYY-MM-DD を作成してください。
- 日付を固定値にしないでください。
- 既存の同名ブランチがある場合は、削除や再利用の前に差分を確認して報告してください。
- mainへ直接変更を入れないでください。

対象環境:
- クラウド開発環境: sinyuubuturyuu-dev
- 本番環境: sinyuubuturyuu-86aeb
- ローカルEmulatorとは混同しないでください。

作業条件:
- 最初に実行コード内のFirebase設定、初期化、Service Worker、キャッシュ参照を検索し、現在の影響範囲を確認してください。
- docsに記載された設定ファイル一覧は主要候補であり、固定された完全一覧として扱わないでください。
- 現在の開発用Webアプリ設定を信頼できる管理元で確認し、値を推測しないでください。
- projectIdだけでなく、apiKey、authDomain、storageBucket、messagingSenderId、appIdを開発用設定へ揃えてください。
- measurementIdは開発用設定に存在する場合だけ使用してください。
- Firebaseアプリ再利用時はprojectIdも検査し、本番アプリの取り違えを防いでください。
- 本番と開発でService Workerおよびブラウザキャッシュが混ざらないようにしてください。
- 開発環境であることを画面上で識別できるようにしてください。
- テスト用パスワードやサービスアカウント鍵をコード・docsへ記載しないでください。
- 社員情報訂正機能はまだ修正しないでください。
- Firebaseデータ変更、デプロイ、commit、push、PR作成は行わないでください。

確認:
- 実行対象ソースに本番プロジェクトIDが接続設定として残っていないこと
- projectIdがsinyuubuturyuu-devであること
- 変更したJavaScriptの構文確認とgit diff --check
- 差分が開発環境切替だけであること
- 本番復帰時に取り除く環境差分を一覧化できること

実行時確認は、私が別途依頼した場合だけ行ってください。行う場合は古いService Workerとキャッシュの影響を除き、実際のapp.options.projectIdとAuth・Firestoreの通信先を確認してください。本番へは書き込まないでください。

最後に、ブランチ、基点コミット、変更ファイルと理由、設定の確認元（秘密情報を除く）、確認結果、未確認事項、各種外部操作の有無を報告してください。

新しい手順のポイント

  • 固定7ファイルではなく、最新コードを検索して影響範囲を決めます。
  • 設定値の推測を禁止し、任意項目の measurementId を必須扱いしません。
  • Firebase設定だけでなく、Service Worker・キャッシュ・アプリ再利用も確認します。
  • 環境切替を機能修正から分離し、本番復帰で正確に除去できるようにします。
  • 資格情報をページへ載せず、実行時確認は別途依頼された場合だけ行います。
